# Domain docs

This repo uses a single-context layout: `CONTEXT.md` at the root and ADRs in `docs/adr/`.

Before exploring a domain area, read the root `CONTEXT.md` and relevant ADRs when they exist. Proceed silently if they do not exist; `/domain-modeling` creates them when domain terms or decisions are resolved.

Use terms defined in `CONTEXT.md` in issues, specs, tests, and proposals. If a needed concept is absent, reconsider the term or note the gap for `/domain-modeling`.

Surface any conflict with an existing ADR explicitly before proposing a different decision.
